# Видение глобального UI

Документ фиксирует продуктовое направление для общего интерфейса LocalPlanner.

LocalPlanner не должен ощущаться как календарь с прикрученными списками. Это должен быть приватный local-first планировщик, где пользователь собирает намерения, организует их в проекты и превращает выбранную работу во время.

## Форма продукта

Приложение организовано вокруг трёх режимов мышления:

- Обзор: что требует внимания сейчас.
- Планирование: куда работа помещается во времени.
- Организация: проекты, рутины, трекеры и долгоживущий контекст.

UI должен давать каждой сущности понятный "дом", но при этом позволять создавать и связывать сущности из любого места приложения.

## Основная навигация

Основная навигация должна жить в постоянном левом сайдбаре.

Рекомендуемые разделы:

- Сегодня
- Планирование
- Задачи
- Проекты
- Рутины
- Трекеры
- Календарь
- Архив
- Настройки

Сайдбар должен подчёркивать, что "Сегодня" и "Планирование" являются главными рабочими поверхностями. Остальные страницы поддерживают организацию отдельных типов сущностей.

## Глобальное создание

В приложении должно быть глобальное действие создания, доступное из сайдбара или верхней панели.

Меню создания:

- Задача
- Таймблок
- Важная дата
- Возможное мероприятие
- Рутина
- Трекер
- Проект

Создание обычно должно открывать правый drawer. Drawer лучше сохраняет контекст, чем отдельная страница или тяжёлое модальное окно. Если пользователь создаёт сущность внутри проекта, этот проект должен подставляться автоматически.

## Drawer-формы создания

Drawer-формы должны начинаться компактно и раскрывать дополнительные поля только при необходимости.

### Задача

Назначение: то, что пользователь должен выполнить.

Поля:

- название;
- проект;
- теги;
- запланированная дата;
- дедлайн;
- оценка длительности;
- приоритет;
- заметки.

Действия:

- создать;
- создать и запланировать;
- создать ещё одну.

### Таймблок

Назначение: зарезервированное время в календаре дня.

Поля:

- название;
- дата;
- время начала;
- время окончания или длительность;
- проект;
- теги;
- связанная задача, опционально;
- заметки.

Таймблок может существовать сам по себе. Он не обязан быть связан с задачей.

### Важная дата

Назначение: напоминание на уровне дня без времени начала и окончания.

Поля:

- название;
- дата;
- повторение;
- утреннее напоминание;
- проект;
- теги;
- заметки.

Примеры: дни рождения, праздники, годовщины и важные даты.

### Возможное мероприятие

Назначение: внешняя возможность, которая может произойти, но не занимает день пользователя, пока он не решит участвовать.

Поля:

- название;
- дата;
- время, опционально;
- время окончания или длительность, опционально;
- место;
- ссылка;
- цена, опционально;
- статус участия: интересно, пойду, не пойду;
- проект;
- теги;
- заметки.

Когда статус участия становится "пойду", приложение может предложить создать таймблок.

### Рутина

Назначение: повторяемое правило, которое автоматически создаёт задачи.

Поля:

- название;
- расписание;
- длительность по умолчанию;
- проект по умолчанию;
- теги по умолчанию;
- окно генерации;
- состояние включения.

Рутины должны генерировать задачи с запланированными датами. После создания сгенерированные задачи ведут себя как обычные задачи.

### Трекер

Назначение: длительная активность с началом, опциональным завершением и возможным прогрессом.

Поля:

- название;
- дата начала;
- дата окончания, опционально;
- статус: активен, пауза, завершён;
- прогресс, опционально;
- проект;
- теги;
- заметки.

Примеры: чтение книги, прохождение игры, курс или длительный личный процесс.

### Проект

Назначение: контекст, который собирает связанные планировочные объекты.

Поля:

- название;
- цвет;
- статус: активен, пауза, завершён;
- описание;
- теги по умолчанию, опционально.

Проекты должны быть видны во всём приложении как фильтр и как контекст создания.

## Ключевые экраны

### Сегодня

"Сегодня" - основная ежедневная рабочая поверхность.

Экран использует двухпанельную структуру:

- левая панель: обзор дня с важным, фокусом, задачами и возможностями;
- правая панель: календарь дня с реально запланированным временем.

Элементы можно перетаскивать из обзора в календарь, чтобы создавать таймблоки. Подробное поведение описано в `docs/day-panel-vision.md`.

### Планирование

"Планирование" - рабочее пространство для раскладки будущих дел.

Полезные представления:

- день;
- неделя;
- месяц;
- лоток незапланированного.

Экран должен поддерживать перетаскивание задач во временные слоты, перенос таймблоков и фильтрацию по проекту или тегу.

### Задачи

"Задачи" - центр управления обязательствами.

Полезные представления:

- Inbox;
- Сегодня;
- Запланированные;
- Дедлайны;
- Просроченные;
- Без даты;
- Выполненные.

Основные действия:

- отметить выполненной;
- запланировать на дату;
- задать дедлайн;
- назначить проект;
- добавить теги;
- запланировать во времени.

### Проекты

Проекты должны работать как сфокусированные рабочие пространства.

Страница проекта должна показывать:

- обзор;
- задачи;
- календарные элементы;
- рутины;
- трекеры;
- заметки или описание.

Проект отвечает на вопрос: "Что происходит в этой области жизни?"

### Рутины

"Рутины" управляют генерацией повторяющихся задач.

Основные действия:

- включить или выключить;
- изменить расписание;
- предварительно посмотреть сгенерированные задачи;
- посмотреть историю выполнения.

### Трекеры

"Трекеры" управляют длительными активностями.

Основные действия:

- начать;
- поставить на паузу;
- продолжить;
- завершить;
- обновить прогресс;
- создать задачу "продолжить сегодня".

### Календарь

"Календарь" - широкое временное представление.

Он может показывать:

- таймблоки;
- важные даты;
- возможные мероприятия.

Календарь полезен для временного обзора, но не должен быть единственным центром приложения.

### Архив

"Архив" содержит выполненные, отменённые и исторические элементы.

Он должен поддерживать поиск и фильтрацию, но не обязан быть ежедневной рабочей поверхностью.

### Настройки

"Настройки" содержат предпочтения приложения.

Начальные настройки:

- начало и конец дня по умолчанию;
- длительность задачи по умолчанию;
- время утреннего напоминания;
- окно генерации рутин;
- локальное хранение и резервные копии.

## Перемещение между сущностями

Приложение должно поддерживать переход от одной планировочной концепции к другой через создание связей, а не через превращение одной сущности в другую.

Важные связи:

- задача в таймблок: запланировать задачу во времени;
- возможное мероприятие в таймблок: решить участвовать;
- рутина в задачу: сгенерировать запланированную задачу;
- трекер в задачу: создать задачу для продолжения прогресса;
- проект в любую сущность: создать внутри контекста проекта.

Это сохраняет модель понятной:

- задача описывает, что нужно сделать;
- таймблок описывает, когда зарезервировано время;
- важная дата описывает, что нужно помнить сегодня;
- возможное мероприятие описывает, куда можно пойти;
- рутина описывает, что должно регулярно генерироваться;
- трекер описывает длительную активность;
- проект описывает более широкий контекст.

## Принцип навигации

У каждой сущности должен быть один естественный дом, но создание должно работать откуда угодно.

Рекомендуемые дома:

- задачи живут в "Задачах";
- таймблоки, важные даты и возможные мероприятия появляются в "Календаре";
- рутины живут в "Рутинах";
- трекеры живут в "Трекерах";
- проекты собирают всё, что связано с одним контекстом;
- "Сегодня" и "Планирование" объединяют сущности для действия.

Пользователь должен свободно быстро зафиксировать идею, а организовать или запланировать её позже.
