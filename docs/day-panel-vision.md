# Видение панели дня

Документ фиксирует продуктовое направление для экрана планирования дня.

Панель дня должна ощущаться не как классический календарь, а как рабочее место для ежедневного планирования. Слева пользователь видит то, что требует внимания, справа видит форму дня во времени, а свободные намерения можно превратить в запланированные слоты перетаскиванием в календарь.

## Базовая структура

Экран делится на две основные области:

- Левая панель: обзор дня, приоритеты, незапланированные задачи и возможные мероприятия.
- Правая панель: календарь дня с реальными временными слотами и запланированными блоками.

```text
+------------------------------+------------------------------------+
| Обзор дня                    | Календарь дня                      |
|                              |                                    |
| Важное                       | 08:00                              |
| - День рождения              | 09:00  Созвон                      |
| - Дедлайн оплаты домена      | 10:00                              |
|                              | 11:00  Запланированная задача      |
| Фокус                        | 12:00                              |
| - Написать описание проекта  | 13:00                              |
| - Купить подарок             | 14:00                              |
|                              | 15:00  Встреча                     |
| Задачи                       | 16:00                              |
| - Разобрать inbox     30 мин | 17:00                              |
| - Позвонить врачу     15 мин | 18:00                              |
|                              |                                    |
| Возможности                  |                                    |
| - Концерт в 19:00            |                                    |
+------------------------------+------------------------------------+
```

## Левая панель: обзор дня

Левая панель отвечает на вопрос: "Что сегодня требует моего внимания?"

Она не должна показывать внутренние типы сущностей как отдельные тяжёлые разделы. Вместо этого элементы группируются по роли в дне пользователя:

- Важное: просроченные задачи, дедлайны на сегодня и напоминания, привязанные к дате.
- Фокус: одна-три задачи, выбранные вручную или выведенные из приоритета.
- Задачи: задачи, запланированные на сегодня, но ещё не размещённые в календаре.
- Возможности: мероприятия, которые могут произойти, но не занимают время, пока пользователь не решит участвовать.

После планирования в календарь задача должна оставаться видимой в левой панели, но строка должна показывать назначенное время. Так список задач и календарь остаются связанными.

Пример:

```text
Разобрать inbox      11:00-11:30
```

## Правая панель: календарь дня

Правая панель отвечает на вопрос: "Когда это реально произойдёт?"

Она показывает временную сетку текущего дня, например с 06:00 до 23:00. Запланированные блоки отображаются на сетке как записи `TimeBlock`.

Календарь должен поддерживать:

- существующие самостоятельные таймблоки;
- таймблоки, созданные из задач;
- таймблоки, созданные из возможных мероприятий после решения пользователя участвовать;
- изменение длительности блока растягиванием;
- удаление блока без удаления связанной задачи или возможного мероприятия.

## Планирование перетаскиванием

Перетаскивание элемента из обзора в календарь превращает его в запланированное время.

Для задач:

- перетаскивание `Task` в слот календаря создаёт `TimeBlock`;
- `TimeBlock` хранит фактические время начала и окончания;
- задача остаётся источником правды для статуса выполнения;
- если у задачи есть `estimate_minutes`, он используется как длительность по умолчанию;
- если оценки нет, используется стандартная длительность, например 30 минут.

Для возможных мероприятий:

- перетаскивание `OptionalEvent` в календарь означает, что пользователь собирается участвовать;
- `TimeBlock` создаётся по известному временному диапазону, если он есть;
- если время окончания неизвестно, используется разумная длительность по умолчанию.

Удаление сгенерированного таймблока не должно удалять исходную задачу или возможное мероприятие. Оно означает только, что элемент больше не размещён в календаре дня.

## Связи сущностей

Задачи и таймблоки должны оставаться концептуально разными:

```text
Task
- id
- title
- scheduled_date
- due_date
- estimate_minutes
- status

TimeBlock
- id
- title
- start_dt
- end_dt
- linked_task_id?
- linked_optional_event_id?
```

Это сохраняет модель понятной:

- задача описывает, что нужно сделать;
- таймблок описывает, когда зарезервировано время;
- возможное мероприятие описывает внешнюю возможность;
- панель дня является местом, где эти концепции встречаются.

## Продуктовый принцип

При планировании дня пользователь не должен думать в терминах классов сущностей.

Левая сторона собирает внимание. Правая сторона даёт этому вниманию место во времени.
